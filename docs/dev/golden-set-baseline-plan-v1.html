1. 目标（定版）

内置 100 条平台级黄金集，作为检索 / 应答质量的冻结基线，归属系统组织、由超管治理。改动分块 / 检索模型 / 内容清洗 / Rerank / 解析器后回放这 100 题，即可量化质量涨跌。复用现有 Golden Set Replay + LLM-as-Judge + 现有质量看板，不新建看板、不新增指标、不新增 cron。
与 v0.1 一致的前提事实：黄金题 = eval_questions.judge_enabled=TRUE，须绑 KB（org 隔离靠 kb.org_id）；回放走应答 → LLM-Judge（DeepSeek）→ judge_results → judge_metrics_daily → 看板；打分维度含 context_precision / context_recall（检索质量信号）+ faithfulness / answer_relevance。系统组织当前 0 库，故第一步必须建基准库并入库语料。

2. 五个决策点（全部落定）

D1 · 基准库归属：已定 系统组织（org_id=0）下新建 1 个「平台基准库·v1」集中承载（方案 2 集中口径）。语料一库全格式覆盖；扩容到 200 题时再按文档类型拆分为多库（v2）。
D2 · 语料格式：已定 基准语料覆盖全部支持格式——文档 PDF/Word/Markdown/HTML/TXT/CSV + 图片 PNG/JPG/GIF/WEBP（自动 OCR）+ 归档 ZIP/TAR.GZ（用归档上传交付，同时验证服务端展开入库链路）。单文件 ≤ 50MB。
D2+ · 语料质量红线：已定 每份文档必须是有意义、连贯、真实的内容（真实主题、可读段落、有事实可问）。严禁无意义重复文字、随机数字、lorem-ipsum、凑字数填充——否则黄金题问不出真问题、检索命中无意义、基线失真。CSV 需真实字段与真实数值，图片需含清晰真实文字。
D3 · 度量口径：已定 LLM-Judge 为主（context_precision / context_recall + faithfulness / answer_relevance → overall），复用现有链路、零新增基建。纯检索命中率（eval_experiments top-k / MRR）属 Core Set 之外扩展，本期不做。
D4 · 交付方式：已定 超管在系统组织内建库、上传全格式语料入库；100 题经 POST /eval/…/questions/batch 批量导入并置 judge_enabled=TRUE。题干与 expected_text_snippets 随后用 Flyway seed 按 dataset 名固化以便环境复现；不硬编码 chunk_id。
D5 · 冻结机制：已定 eval_questions 加列 is_core BOOLEAN DEFAULT FALSE + 3 处守卫（update/delete 命中核心题抛 403 CORE_QUESTION_LOCKED；EvaluationLab.vue 加 🔒 徽章 + 禁用编辑/删除）。

3. 基准语料 · 全格式覆盖矩阵

一个「平台基准库·v1」内，按格式各备至少 1~2 份稳定、脱敏、可版本化的文档；每种格式挂对应黄金题，使格式相关的解析/OCR 回归可被单独发现。

🔴 语料质量红线：所有文档必须是有意义的真实内容——真实主题、连贯段落、有事实可供提问。禁止无意义重复文字、随机数字、lorem-ipsum、凑字数填充。CSV 用真实字段+真实数值，图片含清晰真实文字。基线的可信度取决于语料的真实性。

5. 基线判读

  • 建基线：100 题首次全量回放后，记录 overall_score 与 context_precision/recall 的 p50/p95 为基线分（存现有 judge_metrics_daily）。
  • 回归：改动后再回放，看现有质量看板同维度日趋势涨跌定位退化；按 judge_tags 可下钻到"哪种格式/哪类难度"退化。不新建差分看板。
  • 成本：单题 DeepSeek judge ≈ ¥0.016，100 题 ≈ ¥1.6/次，受 org_judge_budget 保护，无预算风险。

7. 非目标 / 风险

  • 非目标：不新建看板 / 指标（含 RETRIEVAL_HIT_RATE、ANSWER_CORRECTNESS）/ cron，不做版本差分——严守 Core Set 收敛。
  • chunk_id 不稳定：seed 用 expected_text_snippets 而非 chunk_id；黄金回放本身无需 expected chunk。
  • 语料隐私：全部脱敏 / 公开可版本化，敏感内容不入基线。
  • 内容漂移：基准库文档冻结，不随业务更新；更新走 v2 并重记基线分。
  • 图片/OCR 语料：需含清晰文字，否则 OCR 题无稳定命中；GIF/WEBP 以含文字图为准。
