1决策纪要（本版已确认）

  • 系统组织方向：认可。把 org_id=0 正式定义为系统组织，默认绑超管账号 185****0934（userId=4）。
  • 成员构成：系统组织里的成员都是超管；个人组织 = 超管的私人空间（互不混）。
  • 活动归属：超管的一切活动都在（系统）组织内进行 → 用量/成本天然归系统组织。
  • judge 成本：归系统组织（评测判分记 org=系统组织，不再是无主的 org_id=0）。
  • 跨组织访问：取消全局"全平台视图"，改为按 Tab 的"提权审计"开关，提权后可关闭、可随时切换。

动机：若"超管=个人组织"，单超管勉强、多超管必崩（邀请第 2、3 个超管后各有各的个人组织，平台统计散、平台成本无主）。系统组织让多超管共享同一份平台身份与统计。

2三概念模型（边界分清）

概念是什么身份/成本跨组织
系统组织平台团队自己的工作区（org_id=0，绑超管）成员皆超管；平台级资源(基准库/Core Set)与平台级成本(judge)归此；超管默认在此活动否（就是平台方自己的）
个人组织每个超管的私人空间个人自己的库/成本否
提权（按 Tab）临时、留审计的跨组织"读"，在具体 Tab 上开关不拥有资源、不记成本是（开=看全平台，关=回系统组织）
与旧版差异：旧"全平台视图"是全局切换（切一次到处生效、还会粘住）；新方案是按 Tab 的局部开关——只在你需要的那个页面提权，看完即关，互不影响。

默认（未提权）一律只看系统组织数据；仅带提权按钮的 5 个 Tab 可临时跨组织看全平台（留审计）。

🔍 检索调试台系统组织库检索✕ 无需—
💬 应答调试台系统组织库应答✕ 无需—

小结：5 个放提权按钮（驾驶舱 / 知识库 / 质量看板 / 模型&成本 / 开发者中心），4 个无需提权（检索 / 应答 / 性能 / 评测）。

4"提权审计"开关 · 交互

状态按钮行为
🛡 未提权「提权查看全平台 · 审计」页面只显示系统组织数据（默认）
点击 →弹窗 · 必填访问理由 → 确认进入（不能一键随意提权）该 Tab 请求带 X-Admin-Override，写审计（谁/何时/哪个页面/填写的理由）
🔓 已提权「已提权 · 全平台（点击关闭）」显示全平台数据；再次点击即关闭，回到系统组织
  • 提权是按 Tab 局部生效：在"模型&成本"提权，不影响"知识库管理"。
  • 开启必弹窗、必填理由（写入审计）；关闭为一键（再点一次按钮）。
  • 可随时开/关切换；离开页面或刷新默认回到未提权（不粘住）。
  • 技术上复用现有 AdminOverrideHolder / X-Admin-Override 机制，由按钮按 Tab 触发，服务端照旧写破玻璃审计。
