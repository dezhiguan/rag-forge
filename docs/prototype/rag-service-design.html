PART 01项目定位：这不是聊天应用，是知识引擎

维度RAGForge（本项目）CareerMate（项目二）
定位基础设施层 —— 知识检索 API 服务应用层 —— 求职 Agent 智能体
用户开发者 / 管理员求职者
核心能力文档处理 · 混合检索 · 评测框架 · API 服务任务规划 · 工具调用 · 多步推理 · 记忆管理
页面数量6 个（管理后台型）5 个（用户应用型）
与对方关系提供 RESTful API 给 Agent 调用通过 API 调用 RAGForge 的检索能力
🎯 一句话区分

RAGForge 回答"知识从哪里来、怎么检索、质量如何"——给开发者用的。
CareerMate 回答"怎么帮求职者找到合适的工作"——给用户用的。
两者通过 API 连接：CareerMate 的 Agent 调用 RAGForge 的检索接口获取知识。

🎯 推荐浏览顺序

从 ① 到 ⑥ 是推荐的浏览路线。这不是线性流程，而是层层递进展示工程深度： 先让人看到"这是个产品"（驾驶舱），再展示"怎么管理知识"（知识库），然后深入"核心检索技术"（调试台），再用数据证明"质量可靠"（评测实验室），收尾展示"怎么被 Agent 调用"（API网关）。
