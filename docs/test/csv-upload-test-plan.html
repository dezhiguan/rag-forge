测试目标与打法
验证 CSV「行即 chunk + 表头前缀」入库正确;重点不是走通正路,而是打穿真实世界 CSV 的脏数据——中文 Excel 导出(GBK+BOM+CRLF)、引号/换行嵌套、分隔符嗅探误判、列数错位、序列化分隔符冲突、管道路由错走 HTML/Tika、大表 OOM。不友好的错误提示也算 bug(承接既有验收口径)。

0.测试约定

  • 环境:云端 ragforge.net(生产口径),散传(POST /documents multipart)+ 压缩包内 CSV 两条通道都测;必要时本地单测补充解析层。
  • 判定链:上传受理 → text/csv 路由 → CSV→行文本转换 → 分块 → 向量化 → 检索命中 → 三层展示。任一环错即 fail。
  • 验证维度:① 是否受理 ② 行数=数据行数(不含表头) ③ 每 chunk 是否带表头前缀 ④ 值是否完整无截断/无脏字符 ⑤ 检索能否命中 ⑥ 失败提示是否中文友好。
  • 优先级:P0 核心/高发脏数据 · P1 常见边界 · P2 极端/罕见。深挖 = 高概率隐藏 bug。
  • 决策依赖:部分预期取决于设计稿 D1~D5,未定项在 §15 前置校准列出,执行时作为待澄清项反馈。

15.隐藏 bug 深挖清单 + 前置校准

12 个最可能翻车的隐藏点(执行时重点盯)
  1. GBK 编码(CSV-ENC-03/06):中文 Excel 默认 GBK,按 UTF-8 读整屏乱码——真实世界最高发。
  2. BOM 污染首列名(CSV-HDR-05/ENC-02):首列名变 ﻿姓名,所有行第一列标签错。
  3. CRLF 尾随 \r(CSV-EOL-02):每行末列值带隐藏 \r,检索/展示脏。
  4. 引号内换行被当新行(CSV-FMT-02):行数暴增、列错位。
  5. 分隔符嗅探误判(CSV-DELIM-02/04):; 表整行成单列,或被值里 ; 带偏。
  6. 无表头误吞首行(CSV-HDR-02):第一条数据被当表头静默丢失。
  7. 列数错位(CSV-MAL-01/02):缺列/多列导致后续列左移,值张冠李戴。
  8. 序列化分隔符冲突(CSV-VAL-01):值含 ；/: 破坏 列名: 值； 结构。
  9. 路由错走 HTML/Tika(CSV-RT-01/03):csv 被当 html 剥标签或落 octet-stream 误路由。
  10. 大表 OOM(CSV-LIM-02):非流式解析百万行拖垮 worker。
  11. 仅表头/空表假成功(CSV-EMPTY-02):0 数据行却报成功、0 chunk。
  12. 数字前导 0 丢失(CSV-VAL-06):0012 被当数字变 12。

前置校准(执行前需与研发确认,取决于设计稿 D1~D5)

  • D1 分块粒度:多行打包 vs 一行一 chunk → 影响 CSV-SR-02 跨行边界判定。
  • D2 表头假设:无表头策略 → 决定 CSV-HDR-02 预期。
  • D3 分隔符:是否嗅探 ;/\t → 决定 CSV-DELIM-02/03 预期。
  • D4 护栏阈值:行数/字符上限具体值 → 决定 CSV-LIM-01 断言点。
  • 编码策略:是否支持 GBK 回退(设计稿仅说"UTF-8 优先/非 UTF-8 尽力而为")→ CSV-ENC-03 是"须支持"还是"友好拒绝",须明确。
