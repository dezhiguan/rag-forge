## 测试目标与打法

验证 CSV「行即 chunk + 表头前缀」入库正确；**重点不是走通正路，而是打穿真实世界 CSV 的脏数据**——中文 Excel 导出（GBK+BOM+CRLF）、引号/换行嵌套、分隔符嗅探误判、列数错位、序列化分隔符冲突、管道路由错走 HTML/Tika、大表 OOM。**不友好的错误提示也算 bug**（承接既有验收口径）。

## 0. 测试约定

- **环境**：云端 ragforge.net（生产口径），散传（`POST /documents` multipart）+ 压缩包内 CSV 两条通道都测；必要时本地单测补充解析层。
- **判定链**：上传受理 → `text/csv` 路由 → CSV→行文本转换 → 分块 → 向量化 → 检索命中 → 三层展示。任一环错即 fail。
- **验证维度**：① 是否受理 ② 行数=数据行数(不含表头) ③ 每 chunk 是否带表头前缀 ④ 值是否完整无截断/无脏字符 ⑤ 检索能否命中 ⑥ 失败提示是否中文友好。
- **优先级**：`P0` 核心/高发脏数据 · `P1` 常见边界 · `P2` 极端/罕见。**[深挖]** = 高概率隐藏 bug。
- **决策依赖**：部分预期取决于设计稿 D1~D5，未定项在 §15 前置校准列出，执行时作为待澄清项反馈。

**测试域**：1 正常路径 · 2 解析格式 · 3 表头 · 4 分隔符 · 5 编码 · 6 换行符 · 7 畸形/列错位 · 8 空/退化 · 9 值内容极端 · 10 护栏/规模 · 11 注入/安全 · 12 管道路由 · 13 前后端一致性 · 14 检索质量 · 15 隐藏 bug 深挖 + 前置校准

## 1. 正常路径 CSV-HP

| ID | 场景 | 输入 | 预期 | 级 |
|---|---|---|---|---|
| CSV-HP-01 | 标准 CSV 散传 | 表头+3 数据行，UTF-8，逗号 | 受理→3 行各成可入库文本，每行带 `列名: 值` 前缀 | P0 |
| CSV-HP-02 | 压缩包内 CSV | zip 含 data.csv | 子文档 `contentType=text/csv`，平铺入库，「来自 xx.zip」标识 | P0 |
| CSV-HP-03 | 记录级检索 | 入库后检索某行关键词 | 命中对应行 chunk，表头语义在 | P0 |
| CSV-HP-04 | 多列宽表(合理) | 20 列 × 50 行 | 每行拼全 20 列，无丢列 | P1 |
| CSV-HP-05 | 纯中文内容 | 中文表头+中文值，UTF-8 | 无乱码，检索中文命中 | P0 |

## 2. 解析格式 CSV-FMT（RFC 4180 + 真实世界）

| ID | 场景 | 输入 | 预期 | 级 |
|---|---|---|---|---|
| CSV-FMT-01 | 引号包裹含逗号 | `"北京,海淀"` 作一个值 | 不拆列，值=`北京,海淀` | P0 |
| CSV-FMT-02 | 引号内含换行 **[深挖]** | 字段 `"第一行\n第二行"` | 单元格保留换行，**不被当成新数据行**（错则行数暴增/错位） | P0 |
| CSV-FMT-03 | 转义双引号 | `"他说""你好"""` | 值=`他说"你好"` | P1 |
| CSV-FMT-04 | 空字段 | `a,,c` | 中列空值，不错位 | P0 |
| CSV-FMT-05 | 尾随逗号 | `a,b,` | 末列空值，列数=3 | P1 |
| CSV-FMT-06 | 单列(无分隔符) | 每行一个值 | 受理，单列入库 | P1 |
| CSV-FMT-07 | 值内前后空格 | ` a , b ` | 明确 trim 策略并一致(记录实际行为) | P2 |
| CSV-FMT-08 | 引号不闭合(畸形) | `"unterminated` | 不崩溃；友好失败或尽力解析，提示中文 | P0 |

## 3. 表头 CSV-HDR

| ID | 场景 | 输入 | 预期 | 级 |
|---|---|---|---|---|
| CSV-HDR-01 | 首行表头 | 正常表头 | 表头拼进每行前缀 | P0 |
| CSV-HDR-02 | 无表头 CSV **[深挖]** | 首行即数据(如全是数字/名字) | 依 D2：首行仍当表头则**第一条数据被吞**+全表列名错误——须确认策略并验证不静默丢数据 | P0 |
| CSV-HDR-03 | 重复列名 **[深挖]** | 表头 `name,name,age` | 序列化 `name: x;name: y` 歧义；须去重/加序号，不丢列 | P1 |
| CSV-HDR-04 | 空列名 | 表头 `,age,` | 空列名有兜底(如 `列1`)，不产生 `: 值` | P1 |
| CSV-HDR-05 | 首列表头带 BOM **[深挖]** | UTF-8-BOM，首列名前有 BOM | BOM 剥除，首列名=`姓名` 而非 `﻿姓名`(经典 bug) | P0 |
| CSV-HDR-06 | 列名超长/特殊字符 | 列名含 `:`、`；`、换行 | 不破坏序列化格式 | P2 |

## 4. 分隔符 CSV-DELIM

| ID | 场景 | 输入 | 预期 | 级 |
|---|---|---|---|---|
| CSV-DELIM-01 | 逗号(默认) | 标准 `,` | 正确分列 | P0 |
| CSV-DELIM-02 | 分号分隔 **[深挖]** | `;` 分隔(中文 Excel/欧洲区常见) | 依 D3 嗅探识别为 `;`；否则整行被当单列(高发 bug) | P0 |
| CSV-DELIM-03 | Tab 分隔(TSV) | `\t` | 识别或明确不支持并友好提示 | P1 |
| CSV-DELIM-04 | 嗅探误判 **[深挖]** | 逗号 CSV，但某些值含 `;` | 仍判为逗号，不被值里的 `;` 带偏 | P0 |
| CSV-DELIM-05 | 嗅探样本不足 | 仅表头一行 / 首行无分隔符 | 兜底逗号，不异常 | P2 |

## 5. 编码 CSV-ENC（隐藏 bug 高发区）

| ID | 场景 | 输入 | 预期 | 级 |
|---|---|---|---|---|
| CSV-ENC-01 | UTF-8 无 BOM | 标准 | 正常 | P0 |
| CSV-ENC-02 | UTF-8 带 BOM **[深挖]** | 文件头 `EF BB BF` | BOM 剥除，首字段无 BOM(见 HDR-05 联动) | P0 |
| CSV-ENC-03 | GBK/GB2312 **[深挖]** | 中文 Excel「另存为 CSV」默认 GBK | **最高发真实 bug**：按 UTF-8 读会整屏乱码。须检测/回退 GBK 或明确不支持并给出可读提示(乱码入库=严重 bug) | P0 |
| CSV-ENC-04 | UTF-16 LE/BE | 带 UTF-16 BOM | 正确解码或友好拒绝，不乱码入库 | P1 |
| CSV-ENC-05 | 非法字节序列 | 混入非法 UTF-8 字节 | 不崩溃；替换/跳过 + log，不整表失败 | P1 |
| CSV-ENC-06 | Excel 全套组合 | GBK + BOM + CRLF 同时 | 综合验证真实 Excel 导出件端到端可用 | P0 |

## 6. 换行符 CSV-EOL

| ID | 场景 | 输入 | 预期 | 级 |
|---|---|---|---|---|
| CSV-EOL-01 | LF | `\n` | 正常分行 | P1 |
| CSV-EOL-02 | CRLF(Windows/Excel) **[深挖]** | `\r\n` | 正常分行，**末列值不带尾随 `\r`**(常见脏字符 bug) | P0 |
| CSV-EOL-03 | CR(老 Mac) | `\r` | 识别或明确行为一致 | P2 |
| CSV-EOL-04 | 末尾无换行 | 最后一行无 EOL | 最后一行不丢 | P1 |
| CSV-EOL-05 | 数据中间空行 | 行间夹空行 | 空行跳过，不产生空记录 chunk | P1 |

## 7. 畸形/列错位 CSV-MAL

| ID | 场景 | 输入 | 预期 | 级 |
|---|---|---|---|---|
| CSV-MAL-01 | 数据列 > 表头列 **[深挖]** | 表头 3 列，某行 5 列 | 多余列有兜底列名，不越界/不丢值/不错位 | P0 |
| CSV-MAL-02 | 数据列 < 表头列 **[深挖]** | 表头 5 列，某行 2 列 | 缺列留空，**不把后续列左移错位** | P0 |
| CSV-MAL-03 | 逐行列数不齐 | 每行列数都不同 | 逐行独立处理，单行畸形不拖垮整表 | P1 |
| CSV-MAL-04 | 全空行混杂 | 数据中大量空行 | 跳过，统计行数正确 | P2 |

## 8. 空/退化 CSV-EMPTY

| ID | 场景 | 输入 | 预期 | 级 |
|---|---|---|---|---|
| CSV-EMPTY-01 | 0 字节文件 | 空文件 | 友好拒绝「文件内容不能为空」，不 NPE | P0 |
| CSV-EMPTY-02 | 仅表头无数据 **[深挖]** | 只有一行表头 | 按「无可入库内容」处理，提示中文，不产生 0 chunk 的成功假象 | P0 |
| CSV-EMPTY-03 | 仅 BOM | 只有 `EF BB BF` | 等同空，友好处理 | P2 |
| CSV-EMPTY-04 | 仅换行/仅分隔符 | `\n\n` 或 `,,,` | 无有效记录，友好处理，不崩溃 | P1 |

## 9. 值内容极端 CSV-VAL

| ID | 场景 | 输入 | 预期 | 级 |
|---|---|---|---|---|
| CSV-VAL-01 | 值含序列化分隔符 **[深挖]** | 值里本身含 `；` 或 `: `(与 `列名: 值；` 冲突) | 序列化不产生歧义/注入(转义或换用分隔)；检索仍可分辨字段边界 | P0 |
| CSV-VAL-02 | 值含 markdown/rfimg **[深挖]** | 值 `![x](rfimg://0)` 或 `<img>` | CSV 不走内嵌图/HTML 路径，原文本入库不被误解析成图 | P1 |
| CSV-VAL-03 | 值含 HTML 标签 | 值 `<b>x</b>` | 不被 HTML strip 误处理(验证路由：csv≠html) | P1 |
| CSV-VAL-04 | 超长单元格 | 单值 1MB 文本 | 受护栏约束，截断/分块合理，不 OOM | P1 |
| CSV-VAL-05 | 纯空白/全空值行 | 行内全空 | 识别为空记录，跳过或明确处理 | P2 |
| CSV-VAL-06 | 数字/日期/科学计数 | `0012`、`1e5`、`2024-01-01` | 保持原文本，不被转成数值丢前导 0 | P1 |

## 10. 护栏/规模 CSV-LIM

| ID | 场景 | 输入 | 预期 | 级 |
|---|---|---|---|---|
| CSV-LIM-01 | 超行数上限 **[深挖]** | 超 D4 行数阈值(如 5 万+) | 截断到上限 + summary/log 明确提示丢弃了多少，**不静默截断** | P0 |
| CSV-LIM-02 | 百万行 OOM **[深挖]** | 百万行大 CSV | 流式解析，内存平稳，不 OOM 拖垮 worker | P0 |
| CSV-LIM-03 | 超宽表(超 chunk) | 单行拼出超 chunk 大小 | 依 D5 正常切，不丢值 | P1 |
| CSV-LIM-04 | 接近 50MB 文件 | ~50MB CSV | 受理上限一致(散传 50MB / 压缩包单 entry 50MB) | P1 |
| CSV-LIM-05 | 压缩包内高压缩比 CSV | zip 内 CSV 解压后极大 | 被压缩包比率/总量护栏拦截，不绕过 | P1 |

## 11. 注入/安全 CSV-SEC

| ID | 场景 | 输入 | 预期 | 级 |
|---|---|---|---|---|
| CSV-SEC-01 | CSV 公式注入 | 值 `=cmd\|'/c calc'`、`@SUM`、`+`/`-` 开头 | 作纯文本入库不执行；记录(仅入库无导出，风险低) | P2 |
| CSV-SEC-02 | 值内海量换行 **[深挖]** | 单引号字段含百万 `\n` | 不导致行数/内存爆炸，受护栏挡 | P1 |
| CSV-SEC-03 | 超长无分隔单行 DoS | 一行几十 MB 无换行 | 解析器不挂死，受大小护栏拦 | P1 |

## 12. 管道路由 CSV-RT（深挖：路由错走会静默出错）

| ID | 场景 | 输入 | 预期 | 级 |
|---|---|---|---|---|
| CSV-RT-01 | 路由不误走 HTML strip **[深挖]** | text/csv 文档 | `resolveText` 命中 csv 特判，**不进 HTML 剥标签分支**(分支顺序：csv 判断须在通用 text/* 处理之前) | P0 |

| CSV-RT-03 | 压缩包 contentType 正确 **[深挖]** | zip 内 .csv | `guessContentType` 返回 `text/csv`，不落 octet-stream 导致误路由 | P0 |
| CSV-RT-04 | 三层展示 | csv 子文档 | 知识库列表/文档列表(来自 xx.zip)/详情三层正常 | P1 |
| CSV-RT-05 | 去重 contentMd5 | 重复上传同 CSV | 按 md5 去重口径一致 | P2 |
| CSV-RT-06 | 重新分块 rechunk | 对 csv 文档 rechunk | 重跑 CSV→行文本一致，不退化成裸文本 | P1 |

## 15. 隐藏 bug 深挖清单 + 前置校准

### 12 个最可能翻车的隐藏点（执行时重点盯）

1. **GBK 编码**（CSV-ENC-03/06）：中文 Excel 默认 GBK，按 UTF-8 读整屏乱码——真实世界最高发。
2. **BOM 污染首列名**（CSV-HDR-05/ENC-02）：首列名变 `﻿姓名`，所有行第一列标签错。
3. **CRLF 尾随 \r**（CSV-EOL-02）：每行末列值带隐藏 `\r`，检索/展示脏。
4. **引号内换行被当新行**（CSV-FMT-02）：行数暴增、列错位。
5. **分隔符嗅探误判**（CSV-DELIM-02/04）：`;` 表整行成单列，或被值里 `;` 带偏。
6. **无表头误吞首行**（CSV-HDR-02）：第一条数据被当表头静默丢失。
7. **列数错位**（CSV-MAL-01/02）：缺列/多列导致后续列左移，值张冠李戴。
8. **序列化分隔符冲突**（CSV-VAL-01）：值含 `；`/`: ` 破坏 `列名: 值；` 结构。
9. **路由错走 HTML/Tika**（CSV-RT-01/03）：csv 被当 html 剥标签或落 octet-stream 误路由。
10. **大表 OOM**（CSV-LIM-02）：非流式解析百万行拖垮 worker。
11. **仅表头/空表假成功**（CSV-EMPTY-02）：0 数据行却报成功、0 chunk。
12. **数字前导 0 丢失**（CSV-VAL-06）：`0012` 被当数字变 `12`。

### 前置校准（执行前需与研发确认，取决于设计稿 D1~D5）

- **D1 分块粒度**：多行打包 vs 一行一 chunk → 影响 CSV-SR-02 跨行边界判定。
- **D2 表头假设**：无表头策略 → 决定 CSV-HDR-02 预期。
- **D3 分隔符**：是否嗅探 `;`/`\t` → 决定 CSV-DELIM-02/03 预期。
- **D4 护栏阈值**：行数/字符上限具体值 → 决定 CSV-LIM-01 断言点。
- **编码策略**：是否支持 GBK 回退（设计稿仅说"UTF-8 优先/非 UTF-8 尽力而为"）→ CSV-ENC-03 是"须支持"还是"友好拒绝"，须明确。
