# RAGForge 多租户隔离与 API Key 授权 — 测试用例集

> 依据:`docs/dev/api-key-authz-redesign.html` v1.0(定版,2026-07-02)
> 执行方式:Playwright e2e(前端 UI)+ 少量 API 直连(REST/MCP 鉴权)
> 说明:本文覆盖**目标(to-be)行为**。标注 `【现状差异】` 的项为当前代码尚未实现、属回归/防退化目标。
> 优先级:P0=阻断/安全,P1=核心功能,P2=体验/边界。类型:功能/权限/边界/异常/安全/回归。

## 约定与环境

- 角色账号 / 组织(测试前准备,**刻意构造跨组织与多重身份以覆盖切换视角**):
  - `ADMIN`:平台超管(可切"全平台视图"破玻璃)
  - **企业组织 A**:`OWNER_A` / `ADMIN_A` / `MEMBER_A`(所有者/管理员/成员)
  - **企业组织 B**:`OWNER_B` / `MEMBER_B`(与 A 完全独立,用于跨组织隔离)
  - **跨组织成员 `USER_X`**:同时是 **A 的 MEMBER + B 的 ADMIN**(专测"同一人切换不同组织→权限随之变")
  - `USER_P`:仅个人组织的普通用户
  - `OWNER_JOB`:持有「求职组织」的运营账号
  - 每个企业组织内各建:1 个 PRIVATE 库、1 个 ORG 库;个人组织各建 1 个 PRIVATE 库
- **视角切换约定**:凡"视角"用例,均通过左上角组织切换器切换 `currentOrgId`(含"全平台视图");每次切换后重新校验 菜单/按钮/列表/行级权限 是否随新组织身份联动。
- 通用断言点:①按钮/菜单显隐 ②接口返回码与 `errorCode` ③toast 文案为**友好中文**(非裸错误码)④数据可见范围
- Playwright 基线:每个写操作后校验 DB/接口一致性;每个权限用例都测"能"与"不能"两侧。
